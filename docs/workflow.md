# 开发流程规范

> BrewLog 版本管理、迭代节奏、发布流程

---

## 版本号规范

### 格式

```
主版本号.次版本号.修订号
Major.Minor.Patch

示例: 1.0.0, 1.1.0, 1.1.1
```

### 递增规则

| 位置 | 名称 | 何时递增 |
|------|------|----------|
| **Major** | 主版本号 | 重大更新、架构重构、不兼容改动 |
| **Minor** | 次版本号 | 新增功能、向后兼容的改进 |
| **Patch** | 修订号 | Bug 修复、小改进 |

### 规则

```
Patch +1  →  Minor 和 Major 不变
Minor +1  →  Patch 归零，Major 不变
Major +1  →  Minor 和 Patch 都归零
```

### 示例

```
1.0.0  →  首次发布
1.0.1  →  修复 Bug
1.0.2  →  又修复 Bug
1.1.0  →  新增 AI 分析功能
1.2.0  →  新增搜索筛选
2.0.0  →  大版本更新（如加入云同步）
```

### 特殊版本

| 格式 | 含义 |
|------|------|
| `0.x.x` | 开发中版本，未正式发布 |
| `x.x.x-alpha` | 内部测试版 |
| `x.x.x-beta` | 公开测试版（本项目跳过） |
| `x.x.x-rc.1` | 候选发布版 |

## 开发迭代阶段

### 阶段定义

```
┌─────────────────────────────────────────────────────────┐
│                      开发阶段                            │
│                                                         │
│   v0.1 ──→ v0.2 ──→ v0.3 ──→ ... ──→ v0.9 ──→ v1.0    │
│    │        │        │              │         │        │
│   搭建    数据模型  列表展示      真机测试   正式发布   │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 迭代版本规划

| 版本 | 目标 | 主要内容 | 验收标准 |
|------|------|----------|----------|
| v0.1 | 项目搭建 | 创建项目、目录结构 | 可编译运行 |
| v0.2 | 数据模型 | 定义 Model、配置 SwiftData | 无运行时错误 |
| v0.3 | 列表展示 | RecordListView、空状态 | 列表可显示 |
| v0.4 | 新建记录 | 表单、保存功能 | 可创建记录 |
| v0.5 | 详情查看 | RecordDetailView | 可查看详情 |
| v0.6 | 编辑删除 | 编辑表单、删除确认 | 可改可删 |
| v0.7 | UI 美化 | 主题色、图标、组件 | 界面美观 |
| v0.8 | 优化打磨 | 交互优化、数据验证 | 体验流畅 |
| v0.9 | 真机测试 | iPhone 安装测试 | 真机正常运行 |
| v1.0 | 正式发布 | 功能完整、无严重 Bug | 可日常使用 |

### 迭代原则

1. **每个版本只做一件事**
   - 不贪多，专注当前目标
   - 完成一个再做下一个

2. **先跑通，再优化**
   - 先实现基本功能
   - 后续版本再美化、优化

3. **快速验证，及时修复**
   - 每个版本都要可运行
   - 发现问题立即修复

4. **小步快跑**
   - 频繁提交
   - 每次提交一个完整的小功能

## 测试阶段

### 阶段说明

| 阶段 | 测试者 | 环境 | 特点 |
|------|--------|------|------|
| **Alpha** | 开发者自己 | 开发环境/模拟器 | 功能不完整，Bug 多 |
| **Beta** | 外部用户 | 真实环境 | 功能基本完整（本项目跳过） |
| **RC** | 内部确认 | 生产环境 | 功能冻结，只修 Bug |
| **正式版** | 所有用户 | 生产环境 | 期望无严重 Bug |

### BrewLog 测试策略

```
开发阶段 (v0.1 - v0.9)
├── Alpha 测试
│   ├── 模拟器测试
│   ├── 自己手机测试
│   └── 发现 Bug 立即修复
│
└── 无 Beta 阶段（跳过）

发布阶段 (v1.0+)
├── RC 确认
│   └── 最终检查，确保无严重问题
│
└── 正式发布
    ├── 自己使用
    └── 或上架 App Store
```

### Alpha 测试检查项

每个版本完成后：

```
□ 代码编译通过，无警告
□ 模拟器运行正常
□ 核心功能可用
□ 无崩溃问题
□ Git 提交记录清晰
```

## 发布流程

### 整体流程

```
开发完成
    │
    ▼
┌─────────────┐
│ Alpha 测试  │  ← 自己在模拟器/真机测试
└──────┬──────┘
       │
       ▼
┌─────────────┐
│    RC      │  ← 最终确认，功能冻结
└──────┬──────┘
       │
       ▼
┌─────────────┐
│  正式发布   │  ← 自己用 / App Store
└─────────────┘
```

### 发布检查清单

```
版本号
□ Version 已更新 (如 1.0.0)
□ Build 号已递增

功能
□ 所有计划功能已完成
□ 核心流程无阻塞 Bug
□ 边界情况已处理

测试
□ 模拟器测试通过
□ 真机测试通过 (iPhone)
□ 不同机型测试 (可选)

代码
□ 无编译警告
□ 无 TODO/FIXME 遗留 (或已记录)
□ 代码已提交

文档
□ CHANGELOG 已更新
□ README 已更新 (如有必要)
```

## Git 工作流

### 分支策略

```
main        ← 稳定版本，随时可发布
  │
  ├── develop    ← 开发分支（可选）
  │     │
  │     ├── feature/ai-analysis    ← 功能分支
  │     └── feature/search
  │
  └── hotfix/xxx    ← 紧急修复
```

### 简化策略（个人项目推荐）

```
main ← 直接在 main 上开发，每个版本打 tag
        │
        ├── v0.1
        ├── v0.2
        ├── ...
        └── v1.0
```

### 提交信息规范

```
<type>: <subject>

type 类型:
- feat:     新功能
- fix:      Bug 修复
- docs:     文档更新
- style:    代码格式（不影响功能）
- refactor: 重构
- test:     测试
- chore:    构建/工具

示例:
feat: Add espresso parameter form
fix: Fix crash when saving empty record
docs: Update API documentation
```

### 版本标签

```bash
# 打标签
git tag -a v0.1.0 -m "v0.1.0: Project setup"
git tag -a v1.0.0 -m "v1.0.0: First release"

# 推送标签
git push origin v0.1.0
git push origin --tags
```

## iOS 版本设置

### Xcode 配置

```
Target → General → Identity

Version (CFBundleShortVersionString)
├── 用户看到的版本号
└── 格式: 1.0.0

Build (CFBundleVersion)
├── 构建号，每次递增
└── 格式: 1, 2, 3... 或 1.0.0.1
```

### 版本更新示例

| 场景 | Version | Build |
|------|---------|-------|
| 首次发布 | 1.0.0 | 1 |
| 同版本修复后重提 | 1.0.0 | 2 |
| Bug 修复版本 | 1.0.1 | 3 |
| 新功能版本 | 1.1.0 | 4 |
| 大版本更新 | 2.0.0 | 5 |
